## 安全前提（先检查）

- 只在**专用测试小程序 AppID / 预览环境**上操作。不要在已有私人记录的正式微信小程序或旧 H5 上做清空测试。
- 如果测试小程序已有任何真实记录，先保存并确认备份，**不要覆盖或清空**，也不要用真实私人简记作为截图素材。
- 以下均使用虚构的测试文本；文件最好发送给自己的「文件传输助手」，不要发送到群聊或不信任的对象。
- 导出文件是明文 JSON，分享给他人后对方可以阅读。分享回调不代表文件已安全保存，必须在聊天里核对。

## 测试准备

1. 用微信扫码最新预览码，进入「今天」；记录微信版本、iOS 版本、手机型号、当前小程序预览构建时间。
2. 今天明确记为 **2** 件，添加简记「测试简记 A：今天仍在学习」，再修改成「测试简记 A：重新理解」。
3. 从日历打开**昨天**，明确记为 **0** 件，再加一条简记「测试简记 B：零也是记录」；这样覆盖 0 与未记录的区别，以及日期、文字修改历史。
4. 检查日历、统计、日期详情的所有内容都正确，记下数字、简记、历史事件条数。**不修改任何私人记录**。

## 必过流程（逐步留结果）

| ID | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| W01 | 设置 → 导出完整备份 | 微信文件分享界面可打开，无白屏、卡死；提示文件包含私人记录 |
| W02 | 选择「文件传输助手」并确认发送 | 在微信聊天中**实际收到** `错事备份_YYYY-MM-DD.json` 文件，可查看文件名和大小 |
| W03 | 返回错事，数字 2 改为 3，再编辑简记 A | 页面内容确实改变，形成可用于验证“恢复会覆盖当前数据”的对照 |
| W04 | 设置 → 导入备份 → 从聊天选择 W02 文件 | 文件选择器可打开，选中的应是**刚发出的 JSON** |
| W05 | 文件格式/校验验证后出现替换确认 | 显示合理的日期和历史条数，明确警告替换当前记录、清理草稿 |
| W06 | 点击取消替换 | 当前 3 件与修改后的简记保持不变，不能偷偷写回 |
| W07 | 再次导入同一备份并确认 | 今天恢复到 **2** 件，简记 A 恢复成「重新理解」，昨天为明确 **0** 件且简记 B 仍在 |
| W08 | 查看日期详情历史 | 简记旧文、历史修改事件、操作时间仍可见；不要只检查当前数字 |
| W09 | 再次导出，并与 W02 JSON 核对记录字段 | 日期、数字、简记及事件历史一致（导出时间 `exportedAt` 可以不同） |
| W10 | 导入时不选择文件/返回上一层 | 应退出选择，不覆盖数据；之后仍能重新进入导入流程 |
| W11 | 微信转后台 1–5 分钟后返回 | 页面不丢失记录，按钮、键盘和日期状态正常 |
| W12 | 断网后进行日常数字与简记操作 | 已有页面的本地记录可正常操作；**分享/聊天文件选择不要求离线可用** |

**附加建议**：如能从电脑制作一份修改过正文但未重算 SHA-256 的测试 JSON 并发给文件传输助手，再尝试导入。预期必须拒绝而且不覆盖本机数据。禁止用私人真实备份做篡改测试。
