# 错事 · 微信 iPhone 真机备份恢复验收

> 状态：**待真人在手机上执行。自动化与微信开发者工具通过不等于本表通过。**
>
> 版本：v0.4.0-alpha.3 首发候选功能集；应使用 release/v0.4-rc1-prep 独立候选构建生成的最新预览码。

请从 [首发候选 CI](https://github.com/ysr666/cuoshi/actions/workflows/ci.yml?query=branch%3Arelease%2Fv0.4-rc1-prep) 的最新 WeChat 测试构建重新生成预览二维码。**原设计 Draft PR 的旧二维码不是该候选包**。设备和微信版本必须在结果表填写。

## 二维码过期或 Mac 暂时离线时的测试包获取

GitHub Actions 在每次 Draft PR 回归通过构建和隔离测试后，上传 **`wechat-preview-<run-id>`** 小程序编译产物（保留 7 天）。可从 [首发候选分支的 Actions 运行记录](https://github.com/ysr666/cuoshi/actions/workflows/ci.yml?query=branch%3Arelease%2Fv0.4-rc1-prep) 打开对应 run → Artifacts，下载 ZIP，解压并在微信开发者工具中**以专用测试 AppID**导入，手动生成最新测试预览二维码。

这是仅供真机验收的**测试构建产物**，不是已发布的小程序、不是微信审核通过的证据，也不会自动导入 Mac 项目或上传任何用户 JSON。仓库公开，因此不要把私人记录、AppSecret、真实手机号或测试登录凭据放入编译包或 CI Artifact。实际真机结果仍须按 W01–W12 填写。

## 用于额外安全验收的三份合成测试 JSON

在 Mac 项目目录运行 `npm run qa:wechat:fixtures`，会在被 Git 忽略的 `qa-output/` 目录生成 **有效模拟备份** 和 **校验和已故意篡改的备份**；如需测试超大文件，再运行 `npm run qa:wechat:fixtures:large` 生成超过 15 MiB 的合成 JSON。工具不读取真实用户存储、聊天记录、现有导出或账号数据。有效备份包含生成当日 2 件、昨天明确 0 件、两条合成简记及 5 条修改事件。

这三份文件用于**附加负面测试**，不是 W01–W12 正式分享闭环的替代品。通过微信 Mac 客户端把合成文件发给自己的文件传输助手，再在**空白的专用测试小程序**选择导入：有效文件应该进入正常二次确认；篡改文件必须拒绝并保留原记录；超大文件必须拒绝读取。有效文件如执行确认恢复，会覆盖测试小程序当前全部记录，因此请先确认没有私人数据。生成日期随本机当前日期变化，使用时检查手机端时区与日期。

## 安全前提（先检查）

- 只在**专用测试小程序 AppID / 预览环境**上操作。不要在已有私人记录的正式微信小程序或旧 H5 上做清空测试。
- 如果测试小程序已有任何真实记录，先保存并确认备份，**不要覆盖或清空**，也不要用真实私人简记作为截图素材。
- 以下均使用虚构的测试文本；文件最好发送给自己的「文件传输助手」，不要发送到群聊或不信任的对象。
- 导出文件是明文 JSON，分享给他人后对方可以阅读。分享回调不代表文件已安全保存，必须在聊天里核对。

## 测试准备

1. 用微信扫码最新预览码，进入「今天」；记录微信版本、iOS 版本、手机型号、当前小程序预览构建时间。
2. 今天明确记为 **2** 件，添加简记「测试简记 A：今天仍在学习」，再修改成「测试简记 A：重新理解」。
3. 从日历打开**昨天**，明确记为 **0** 件，再加一条简记「测试简记 B：零也是记录」；这样覆盖 0 与未记录的区别，以及日期、文字修改历史。
4. 检查日历、统计、日期详情的所有内容都正确，记下数字、简记、历史事件条数。**不修改任何私人记录**。

## 必过流程（逐步留结果）

| ID | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| W01 | 设置 → 导出完整备份 | 微信文件分享界面可打开，无白屏、卡死；提示文件包含私人记录 |
| W02 | 选择「文件传输助手」并确认发送 | 在微信聊天中**实际收到** `错事备份_YYYY-MM-DD.json` 文件，可查看文件名和大小 |
| W03 | 返回错事，数字 2 改为 3，再编辑简记 A | 页面内容确实改变，形成可用于验证“恢复会覆盖当前数据”的对照 |
| W04 | 设置 → 导入备份 → 从聊天选择 W02 文件 | 文件选择器可打开，选中的应是**刚发出的 JSON** |
| W05 | 文件格式/校验验证后出现替换确认 | 显示合理的日期和历史条数，明确警告替换当前记录、清理草稿 |
| W06 | 点击取消替换 | 当前 3 件与修改后的简记保持不变，不能偷偷写回 |
| W07 | 再次导入同一备份并确认 | 今天恢复到 **2** 件，简记 A 恢复成「重新理解」，昨天为明确 **0** 件且简记 B 仍在 |
| W08 | 查看日期详情历史 | 简记旧文、历史修改事件、操作时间仍可见；不要只检查当前数字 |
| W09 | 再次导出，并与 W02 JSON 核对记录字段 | 日期、数字、简记及事件历史一致（导出时间 `exportedAt` 可以不同） |
| W10 | 导入时不选择文件/返回上一层 | 应退出选择，不覆盖数据；之后仍能重新进入导入流程 |
| W11 | 微信转后台 1–5 分钟后返回 | 页面不丢失记录，按钮、键盘和日期状态正常 |
| W12 | 断网后进行日常数字与简记操作 | 已有页面的本地记录可正常操作；**分享/聊天文件选择不要求离线可用** |

**附加检查**：在专用测试 AppID 的测试聊天中使用体积超过 15 MB 的**合成 JSON 文件**验证微信是否在读取前拒绝导入；若文件选择器不给出大小，检查实际微信能否获取文件系统字节数或友好地提示无法确认大小。不要对真实用户私人 JSON 做大文件测试，不把此模拟检查误作 W01–W12 已通过。

**附加建议**：如能从电脑制作一份修改过正文但未重算 SHA-256 的测试 JSON 并发给文件传输助手，再尝试导入。预期必须拒绝而且不覆盖本机数据。禁止用私人真实备份做篡改测试。

## 准予首发的门槛

必须 W01–W10 全部通过；W11、W12 至少无数据丢失或崩溃；若存在分享 API 在 iOS 上不可用、备份文件根本未送达、恢复丢历史、草稿或隐私提示不符，**阻止首发版本冻结**。其他设备体验可以后续补，但不得掩盖上述阻断项。
