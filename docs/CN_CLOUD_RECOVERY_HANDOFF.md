# 错事 · 云备份恢复安全流程（未来版本）

> 本文为独立纯逻辑与自动化验收合同，**尚无真实云账户、服务器或小程序恢复 UI**。不会改变 v0.4 本地 JSON 备份逻辑。

## 已实现

- `future/cloud/recoveryPlan.ts`：验证经过认证的账号 ID、云快照修订号、完整内容与摘要；生成只含日期数、明确 0、纯文字日、简记数与历史事件数的预览。
- 本机空白、云端不存在、两端完全相同、两端存在差异分别呈现不同状态，不将**明确 0**误判为未记录，不将纯文字简记误判为无数据。
- 本机只要存在记录或未同步的主题偏好，就不静默覆盖；必须由用户明确选择用云备份替换本机，并输入确认文本。
- 本机与云端冲突时，必须先完成本地 JSON 导出并确认已安全保存；校验该文件结构和 SHA-256 与当前本机快照一致。恢复前再次核对本地/云端内容和云版本，变更后直接拒绝过期预览。
- 不自动合并 divergent 历史，更不会删除云端另一设备的修改。恢复函数只返回**深拷贝**的候选记录；将其原子写入本机存储及失败回滚还需独立 UI/存储实现。
- 自动测试覆盖：账号不匹配、摘要损坏、旧版本预览、零/空白/纯文字区分、历史保留、未导出本机冲突、不正确确认与深拷贝。

## 仍需上线前验收

微信真实登录、云端上传/下载接口、用户主动开启、恢复 UI 与安全区/键盘处理、JSON 确实保存或发送成功、失败回滚与本地数据一致性、跨设备冲突处理及真机测试。**没有任何自动上传或覆盖用户现有数据的功能。**

与已完成的本地微信备份功能不同，云恢复必须同时核对真实服务器账号所有权、云快照版本以及同步状态，不得仅依赖前端传入的用户 ID。
