# 中国大陆云备份后端 · 安全与上线交接（2026-10-16）

> **独立未来版本工程，尚未对用户开放**。此清单用于明确完成、未完成及上线前必须人工确认的事项。不能把合约测试或本地数据库测试等同于微信正式登录、备案或安全评估。

## 已落地的工程

- **数据库权限分离**：`sql/002_runtime_permissions.sql` 为数据库迁移者、云备份服务角色、管理员服务角色建立不同权限。备份角色无法访问管理员工单/审计表；管理员角色没有直接查询 `cloud_snapshots`、修改权限表、清空审计等权限。
- **受限、可审计的 SQL 读取函数**：`cloud_read_day` 内部核验员工角色、工单状态、用户、指定日期、审批人是否仍有效、最多两小时授权及多因素认证状态。用数据库锁减少授权撤销的并发竞态。审计写入失败时不会返回正文。
- **快照事务**：对同一账号加行锁、幂等回执、历史事件全量校验；不支持把并发另一设备数据静默覆盖。
- **会话验证边界**：`sessionTokens.ts` 为未来经过真实身份核验的账号、员工签发短期 HMAC 会话，普通用户最长 15 分钟，员工最多 5 分钟且要求近期 MFA；签名与听众分离，敏感密钥不可硬编码或在客户端下发。
- **强制认证调用适配器**：`authenticatedService.ts` 先验证签名、有效期及会话用途，再调用受限数据库事务与读取接口。它不是 HTTP 服务，没有微信/手机身份签发能力，也没有通用测试后门。
- **用户可见备份状态**：后端已可给已验证用户读取是否开启、是否仍有存储的备份、最新版本号与成功提交时间。关闭云备份不代表删除既存快照，用户必须主动操作删除。
- **验证**：真实低权限 PostgreSQL 登录账号、数据库审计失败防泄露、首次与增量并发、重复请求、非法 SQL 权限、禁用员工/审批人、授权撤销竞态等 **225 项集成检查**；签名会话另有 **40 项检查**。两套均只使用合成账号和记录。

## 微信登录代码已准备但未真实连接

- `src/wechatIdentity.ts` 固定调用微信官方 `code2Session` 的 HTTPS 接口，只提取经过验证的 openid 并生成随机内部账户；映射标识及登录临时代码只保存服务端 HMAC 摘要。
- 身份专用数据库角色仅有身份映射所需最低权限，无权查看私人快照或删除用户数据；并发首次登录在事务中锁定同一身份，临时代码只使用一次。
- 会话注销支持用户/管理员各自持久拒绝名单，密钥轮换允许在旧令牌有效期内暂时保留前任密钥，且未接入真实 AppID/AppSecret、生产密钥管理或可公开使用的后端接口。
- 最关键的边界、仍未实现的全局失效与客户隐私风险见 [微信登录与会话生命周期](CN_CLOUD_WECHAT_AUTH_HANDOFF.md)。

## 正确的身份接入顺序（不能跳过）

1. **微信账号认证**：正式小程序 AppID 和服务端 AppSecret（仅在服务器保管，绝不下发小程序）；服务端通过微信官方登录流程验证临时代码并获得可信微信身份，再映射**内部 userId**。不可将客户端自填的 openid、手机号或 userId 当成身份。
2. **手机号验证**：验证短信资格和供应商，号码校验、验证码时效、错误次数/频率限制、换绑和注销。没有实际短信供应商与实名条件前不开放此入口。
3. **后台员工身份**：员工独立登录，多因素验证，服务端从数据库获取员工状态/角色。不能以传来的 staffId、role、MFA=true 直接视为授权。
4. **密钥与会话**：正式上线前在国内可信密钥管理服务中存储**两把不同**签名密钥，支持轮换、会话注销、异常设备撤销、防重放策略和安全速率限制；当前代码已提供持久的单令牌退出撤销、当前/前任签名密钥验证；仍缺自动 KMS 轮换、跨设备全局撤销、异常设备失窃响应及真实认证供应商。
5. 所有对外 API 必须来自上述真实身份核验流程，并额外处理 HTTPS、CSRF/跨域策略（视认证方式）、限流、请求体大小、日志脱敏和错误语义，**禁止把数据库仓储函数直接挂到公开路由**。

## 账号注销已实现的数据库边界

未来后端新增独立的用户账号注销事务，并以受限角色分离：用户本人签名会话+二次确认；删除微信身份映射、云备份正文、修改历史、相关工单授权；将原审计记录去标识化；**后台只留粗粒度月度统计与脱敏安全日志**。运行时账号墓碑在 24 小时安全窗口后由独立维护角色清理，过期凭据摘要也有清理函数。

该功能 **未上真实微信或云后端**，不存在已经通过隐私备案或全备份删除验收的结论。独立详细文档：[账号注销与后台留存](CN_ACCOUNT_CANCELLATION_POLICY.md)。

## 必须遵守的操作边界

- `future/server/sql/001_initial.sql` 必须由可信迁移账号运行，**不使用**备份或管理员运行时账号创建表。
- `002_runtime_permissions.sql` 是含 `__SCHEMA__`、`__BACKUP_ROLE__`、`__ADMIN_ROLE__` 占位符的**部署模板**，只能由可信部署流程对经过校验的 SQL 标识符进行渲染。切勿允许浏览器请求携带数据库角色、Schema 名或 SQL 片段。
- 备份/管理员角色不得是超级用户，也不能拥有 Schema；数据库函数的 `SECURITY DEFINER` 所有者必须为可审计、不可由运行时应用登录的迁移角色，并固定安全的 `search_path`。
- 生产环境不能把此目录下的测试密码、伪造账号、随机构造签名会话的测试流程当作实际登录功能。
- 任何数据库敏感读取需要记录主体、理由、案件、时间、结果；日志中不得保存正文。跨设备同步上线前还需冲突合并和恢复交互设计。

**CI 可复现**：`npm run test:future:auth`、`npm run check:types --prefix future/server`、以及使用仅本机临时数据库运行 `npm test --prefix future/server`。完整构建后执行 `npm run test:future:isolation`，验证未来后端未进入 v0.4 小程序包。
