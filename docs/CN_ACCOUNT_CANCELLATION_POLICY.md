# 错事 · 账号注销与后台数据留存规则（未来云服务）

> 设计和数据库原型日期：2026-10-16。**没有上线到微信小程序，没有接触真实用户数据。** v0.4 仍为本地记录产品。

## 用户要求与合规边界

已确定的产品要求：**支持用户注销账号，同时保留必要的后台运营数据**。不能将“后台数据保留”理解成“已注销用户的错事正文、历史简记、微信身份和私人云备份永远留给管理员看”。

中国大陆《个人信息保护法》第十九条、第四十七条，以及《网络数据安全管理条例》第二十三、二十四条规定了最短必要保存期限、注销后删除或匿名化及法定保存例外。需依法保存的资料，应记录具体适用依据与期限；不能只凭“运营需要”永久保存正文。

权威依据：
- [《个人信息保护法》](https://gzca.miit.gov.cn/zwgk/zcwj/zcfg/art/2021/art_98dffb76ef944db68c10194618c72559.html)
- [《网络数据安全管理条例》](https://app.www.gov.cn/govdata/gov/202409/30/520076/article.html)

## 未来用户看到的注销确认

正式实现 UI 时，清晰地告知：

1. 注销后**无法再使用原账号和原云备份恢复旧数据**。建议先自行导出 JSON，必要时确认导出成功。
2. 注销确认采用明确的二次确认而非误触式单击；若存在合理身份核验要求，应通过本人验证，但不能设置不合理阻碍。
3. 服务器处理后，原账号和微信映射注销，云端数字、简记、历史与快照全部删除；所有旧会话、设备的云访问一并失效。**当前设备本地数据是否保留要独立询问，不得自动误删用户本地文件。**
4. 后台仍可能保存与个人无法关联的月度统计、删除后已去标识化的员工安全访问审计，以及依法有明确依据且未满保存期限的数据；具体留存类别、目的与期限必须在隐私政策真实披露。
5. 若另行注册新账号，将是新内部账号；之前的云备份不会自动复活。

## 已实现的 PostgreSQL 注销事务

`future/server/sql/005_account_cancellation.sql` 与 `src/accountCancellation.ts` 在独立数据库环境中执行原子化注销：

- 独立 **deletion service** 角色仅能执行 `cloud_cancel_account` 受限函数；常规 backup/admin/identity/reporting 角色均不能直接调用。
- 只有签名有效、未撤销的**当前用户**可通过隔离后端 `AuthenticatedCloudService.cancelAccount` 调用；用户必须输入完整二次确认文本。没有普通公开 HTTP 接口。
- 同一事务中：标记账号注销、关闭云功能并撤销本次同意；移除微信账号映射、云快照、完整历史、幂等回执、客服/审核授权与涉及该用户的案件；安全审计保留员工与动作，但移除用户标识、私人日期与案件关联。
- 内部 user ID 暂时保留为无法登录的**墓碑**，阻断仍处于最长 15 分钟有效期内的旧令牌；独立维护角色在超过 24 小时后彻底清除墓碑。此 24 小时属于短期安全缓冲，不是永久保存账号。
- 后台仅保存**按月、无用户 ID/正文/原时间明细**的注销数量与被擦除快照数量。独立 **reporting** 账号只有这些统计表的 SELECT 权限，无法查看私人快照、身份映射或员工访问审计。
- 过期登录临时代码摘要、已失效令牌哈希按维护操作定期清理；不保存 bearer 原文。

以上数据库迁移与代码已经在隔离的 PostgreSQL 容器以 **192 项**测试覆盖，包括错误二次确认、其他账号不受影响、授权历史擦除、删除后的旧 JWT 拒绝、统计角色权限、墓碑与哈希清理等。

## “保留后台正文”的严格例外

**未实现、不得默认启用。** 若出现法律/行政法规明确规定尚未届满的保存期限，或其他法律规定的特殊情况，应单独进行法律依据和必要性评估，并满足：

- 留存原因、数据类别、合法依据、批准人、到期时间可核查，非无限期。
- 与正常用户数据隔离，用户注销后停止除法定允许范围内的存储与必要安全保护措施之外的处理；客服和一般内容审核员不得继续阅读这些已注销正文。
- 到期删除或匿名化，包含云对象、缓存、数据库备份与灾备副本的实际清除程序及留痕。若技术上无法立即完成，停止使用该数据并按实际合法要求处理。
- 不因“管理员需要数据”就编造固定 30/90/180 天保存期。

## 尚未完成的生产事项

- 正式微信/手机号登录、注销入口界面、用户真实身份与告知确认；账号绑定、手机更换与注销撤销政策待制定。
- 正式云服务供应商、备案、合法域名、隐私政策、敏感个人信息评估以及可追踪的数据主体请求处理。
- WAL、物理备份、对象存储副本、外部日志、缓存中残余数据的保留与定期删除程序。**本次测试只证明当前数据库事务，不证明所有生产副本已清理。**
- 只保留统计信息并不能自动保证任何使用场景都“彻底匿名”；统计粒度、小样本关联风险仍需上线前评估。
- 密钥管理、失窃设备即时失效、权限审查、独立审计存储、后台只读统计 UI 与告警。

**验收原则**：上线前通过真实用户流程、真实备案和私密数据删除全链路测试。不得把本迁移脚本部署为面向公众可直接调用的数据库接口。
