## 这轮实际实现

1. `src/wechatIdentity.ts`：提供服务器端微信 `code2Session` 请求适配器（固定官方 HTTPS 目的地、5 秒超时、限制响应大小、失败不回显上游凭据）。只接受服务器从微信验证得到的 `openid`，不信任客户端直接填入的身份 ID。
2. `sql/003_wechat_identity.sql`：`cloud_wechat_identities` 使用 AppID 加**服务器 HMAC** 后的用户身份摘要；`cloud_consumed_wechat_codes` 只存临时登录 code 的 HMAC 摘要。后台不保存原始 openid、session_key 或一次性 code。
3. 首次登录生成随机内部 `userId`，老用户复用已有账号；并发首次登录以 **事务级 advisory lock** 序列化，避免两个设备映射到不同账号。登录 code 只可消费一次，即使测试身份交换器意外重复返回成功也会拒绝第二次。
4. **认证数据库角色没有用户删除权限**。此前插入后清理临时用户的算法可能导致身份服务需要 `DELETE cloud_users`（进而可能级联删除备份）；已换为事务锁算法。账号注销未来需独立权限、审批和用户权利流程，不得借微信登录角色执行。
5. `sql/004_session_revocation.sql` 与 `src/sessionRevocation.ts`：对普通备份会话、员工会话建立**各自独立的数据库拒绝名单**。退出只记哈希后令牌 ID，不写入 bearer token；服务实例重启后撤销仍有效。数据库不可达时校验报错、不允许继续读取。
6. `src/authenticatedService.ts`：所有已有服务调用在验证签名后再检查撤销状态；支持**有界的旧密钥过渡期**，新会话只使用当前密钥，移除旧密钥后不再验证旧令牌。用户和管理员密钥互不混用，原有令牌最长 15 分钟/5 分钟。
7. `tests/check-postgres.mjs`：**192 项真实 PostgreSQL 集成测试**，其中新增微信首次登录、复登、并发同用户映射、临时代码抢占、越权 SQL、无效上游响应、DB 持久化退出、密钥轮换。测试全部使用假 AppID、假 code、模拟官方响应、假记录，**没有向微信真实接口发送任何请求**。

## 关键安全边界和残余风险

- `loginWithWechatCode` 接受注入的 `WechatExchange`，用于**可信服务端适配器和离线测试**。生产必须使用受控的 `makeWechatCodeExchanger`、正式密钥与确认的 AppID；如果外层任意接收客户端“verified identity”，则失去身份认证意义。不得将该内部函数或开发测试替身直接作为公开 API。
- HMAC 身份映射与临时代码拒绝名单保存在服务端；pepper 丢失将影响相同 openid 找回原用户，需密钥备份与安全轮换方案。原始 AppSecret 与 pepper 均不得出现在客户端或监控日志。
- 当前已实现**单会话**退出失效，服务执行前做撤销查询。*对已经通过检查且正在执行中的请求，撤销不能必然中断该事务*；未来要通过事务内二次核验、会话 epoch 和设备级失效处理高风险立即封禁。
- 两把密钥过渡仅限原令牌剩余 TTL；尚无 KMS 自动轮换调度、密钥泄露追踪、异常登录告警或员工强制注销所有设备。
- 登录临时代码哈希和过期令牌哈希有数据库累积；正式服务需要具备合法保存期限及受控后台清理策略，操作日志不可存储明文私密简记。
- 数据库函数仅根据签名经认证服务传入的员工 ID/MFA 状态授权；一旦**管理员数据库运行时账号本身被盗**，攻击者仍可能冒用已批准的员工。上线前还需采用更严格的身份绑定、私有网络与审计存储，不能因此声明“数据库已完全消灭管理员滥权可能”。
- 不做账户登录时，v0.4 仍能完全离线记录。未来开启云备份须明确告知内容、旧修改文本、可被限定条件访问的云端正文，给用户选择和删除权。

### 全设备登录会话管理（隔离工程）

迁移 `006_global_session_revocation.sql` 存储账号代际号，`logoutAllUser` 一次强制退出全部设备；重新微信验证后才签发新代际号 JWT。注销事务同时清理可关联原账号的旧令牌撤销记录。当前只保证旧令牌对新请求失效及云写入事务的版本复核；已经进入数据库处理流程的普通只读请求仍须在正式部署前评估强制取消和访问审计的时序。
