# 错事 v0.5 · 独立微信原生测试包

此目录只属于 Draft PR #4；`npm run build:future:mp-weixin` 在被 git 忽略的
`future/.generated-mp` 中生成独立源码和 `dist/build/mp-weixin`。
与 v0.4 的 `src/main.ts`、`src/pages.json`、`dist/build/mp-weixin` 完全分开。

可将生成目录导入微信开发者工具观察真实原生页面和首次告知。
默认 **无公网服务域名、无 AppID、不登录、不上传记录**。接真实服务须显式提供
`CUOSHI_V05_CLOUD_ORIGIN=https://...` 与经批准的隐私告知版本，再由微信
开发者工具配置合法 AppID、请求域名白名单，并准备对应真实后端。切勿把任何
AppSecret、令牌、用户数据或真实个人信息写入该构建配置。

保存完整历史/简记和账号归属由 `future/cloud/uniCloudHost.ts`、
`uniAccountRecords.ts`、`cloudRecordActions.ts` 负责。页面只在完成云端
告知和受验证的微信身份后启用记录操作。无法接云时提示而不会假装备份成功。

这是可编译的**原生开发测试包**，不是已通过真机的生产服务；UI 与实际
微信沙箱的账号登录、双机同步、杀进程恢复、离线授权、备案与隐私合规需要继续验收。

## 离线冷启动和安全随机数

原生微信 `wx.getRandomValues` 是唯一允许的请求幂等号与设备标识安全随机数来源（不依赖不确定的 `uni.getRandomValues` 代理）。仅在首次账号归属及云端授权验证完成后允许本机离线冷启动；联网后必须重验微信账号，账号不同则取消前一个账号的离线访问许可并保持原数据隔离。通过 `npm run test:future:mp-weixin:offline` 用虚构账号和模拟云服务专项验证，随后重新编译不含公网域名的安全测试包。

## 2026-10-19 · 会话撤销与离线归属隔离

- 实际运行中的云端同步遇到服务端 401/403、微信账号归属变化或明确的身份校验失败时，立即撤去本页面的账号记录操作、停止旧账号的网络监听，并提示重新核验；**绝不删除既有数字、简记或事件历史**。
- 被撤销账号的旧离线授权不仅从当前内存失效，也写入独立持久隔离标记。即便本机模拟存储的「删除旧授权」操作没有真正生效，断网冷启动仍不得恢复访问。只有成功验证身份且完成服务器授权/云端检查后，才撤去隔离标记并重新绑定账号。
- `npm run test:future:mp-weixin:offline` 现覆盖 33 项虚构账号断言，新增活跃会话被拒、删除故障注入、离线冷启动禁止访问、B 账号重新授权、首次重新登录直接被拒的恢复边界测试。该模拟 HTTP 与本机存储测试不能替代真正微信 `jscode2session` 和多机验收。
- 若设备存储同时拒绝持久隔离标记写入与旧授权删除，运行时会告知不能确认冷启动隔离，而不是宣称安全恢复；生产仍需验证微信存储损坏/权限错误时的系统行为。

## 2026-10-19 · 快照接口的会话拒绝处理

- 之前普通同步与首次关联的备份 GET/PUT 传输有例外路径，会将明确的 HTTP 401/403、已换账号的同步身份误判为一般网络波动，从而留下旧页面可用的风险。现在下载和上传都向云优先控制层保留认证错误身份，直接触发原生页面锁定与持久离线隔离；联网重新验证后仍按原幂等日志补传。
- 账号权限拒绝不删除本地记录，不清空完整事件历史，也不会标为「已同步」。真实网络断开仍按普通「暂未同步」处理；非身份类错误不被擅自升格为注销。
- `npm run test:future:mp-weixin:offline` 扩展为 **43 项**，涵盖「登录状态正常但快照 GET 返回 401」「PUT 返回 403」「断网冷启动保持锁定」「恢复认证后幂等上传未完成的修改」；这仍是微信回调模拟与隔离合成后端，非正式公众号/小程序 AppID 的在线验证。


## 2026-10-19 · 限流或服务暂不可用时的离线保留

- `/v1/auth/wechat` 的 HTTP 429（登录过于频繁）与 5xx（服务器暂时不可用）**不是**认证失败，不能把已验证设备持久标记成已撤销账号。客户端区分 `wechat_session_rate_limited`、`wechat_session_cloud_unavailable` 与真正的身份拒绝（如 401/403），对临时故障显示「暂未同步」并保留本机记录。
- 已经成功验证、且完成云授权和首次同步的账号，可以在限流时保持账号专属本机记录可编辑；再次成功验证微信身份后按持久队列自动补传。**从未完成身份验证与云同步的设备不能因为 429/503 获得离线读取权限**。
- 运行中同步碰到 429 也按暂时不可用处理，不触发账号撤销。原先对真正 401/403、换微信账号、快照接口身份拒绝的锁定与隔离行为保持不变。
- `npm run test:future:wechat-session` 增加 429/503 和 401/403 分流；`npm run test:future:cloud-first` 验证运行中限流与恢复；`npm run test:future:mp-weixin:offline` 使用已编译原生运行时扩展为 **53 项**模拟微信和云接口的断言。所有测试账号均为虚构值，尚未进行微信真机线上服务验收。


## 2026-10-19 · 云端授权关闭后的明确恢复入口

- 如果后端确认某微信账号已关闭云端保存授权，首页与设置页均提供 **「重新确认自动云端保存」** 按钮。用户未主动点此按钮时，普通的前台刷新、重连、检查连接及杀进程后冷启动均不会自动启用授权或上传原记录。
- 数据库原有快照与本机该账号的数字、简记、追加式修改历史继续保留；重新确认并经服务端状态核实后才恢复自动同步。账号验证失败、账号切换及会话撤销仍遵守此前的持久离线隔离规则，不会用重新授权入口绕过身份核验。
- 重新确认期间首页暂不开放数字及简记编辑控件，防止显示“需要确认”时仍通过对话框写入。测试通过 `cloudFirst` 37 项、模拟原生冷启动及同步 63 项，并检查两页原生编译模板均保留确认入口；均非正式微信真机验证。

- 额外覆盖「服务端 GET 授权仍有效、但 PUT 上传前刚撤销授权」：客户端接到 403 `consent_required` 后给出同一明确恢复入口，待上传幂等队列原样保留，再次手动确认后仅完成一次云端提交。


## 2026-10-19 · 独立权限账号注销闭环（开发版本）

- 设置页加入「申请注销账号」→ 完整输入 `注销账号并清除云端记录` → 原生弹窗再次确认。不能在离线环境或未完成微信账号核验的情况下发起；用户选择取消、输入不符时不传送请求。
- 经受信任 HTTPS 后端 `/v1/account/cancel` 返回严格、真实的删除回执后，客户端会清理当前内存 JWT、撤销该设备旧账号的离线访问权限，记下持久的「已注销」状态，阻止下次微信小程序启动立即静默重建账号。旧账号本地数据仅保留在不可见的账号分区中，不会自动迁移给新账号；下一次使用必须主动点「重新开始（创建新账号）」并重新验证微信与云授权。
- 服务端请求失败或无法确认成功（例如 503/请求超时）时不谎称注销，也**不在本机删除原始记录**。如果服务端实际上已提交但回执丢失，下次账号验证可能收到旧账户关闭，此时应交由用户重新开始或客服核对，不能自动恢复旧云端数据。
- 按当前服务端 SQL 设计，账号注销会删除私人云快照、上传幂等记录及微信身份映射；只保留无法按个人回溯的月度删除计数，以及不再包含原用户 ID / 日期 / 工单引用的脱敏安全审计。数据库旧用户墓碑暂存以阻断未过期 JWT，过期后由独立维护角色清理；基础设施备份的独立生命周期仍需部署时验证与告知。
- 合成 HTTP 账号接口专项 **40 项**、客户端微信会话 **46 项**、编译原生运行时 **75 项**（包括失败保留、持久注销锁、阻止隐式注册和新账号空白记录）；正式真实微信客户端、HTTPS 和数据库尚未配置，不能据此声称已在生产完成注销。
